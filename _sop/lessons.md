# 项目教训（活跃经验）

## 龙首阴策略

### 出场逻辑：移动止损优于固定ATR止损
**背景：** 龙首阴策略经过多轮参数优化后持续亏损。核心问题是固定ATR止损止盈无法适应A股的高波动特性。
**规则：** 对高波动短线策略，移动止损（从持仓最高点回撤一定比例出场）效果显著优于固定ATR止损止盈。
**验证：** v35 到 v36 的改进中，移动止损配合自适应跟踪（按ATR动态调整回撤容忍度）将25只标的均收益从-0.15%提升到+0.63%。

### 数据源：腾讯行情API优先
**背景：** 东方财富 push 接口始终返回502，腾讯 qt.gtimg.cn 稳定可靠。
**规则：** A股实时行情优先使用腾讯行情API。

### parquet缓存双目录兼容
**规则：** 读取缓存时先查 data/cache/{code}.parquet，不存在时再查 data/cache/cn/{code}.parquet。

### backtesting.py Position 无公开 price 属性
**规则：** 使用 backtesting.py 时，如需仓位入场价，必须在 buy() 时手动保存 self._entry_price。

### 前复权数据对涨停信号的干扰
**背景：** 前复权将除权折算进历史价格，导致历史涨停板信号几乎消失。
**规则：** 龙首阴策略使用前复权数据时需注意涨停阈值是否被复权价格扭曲，必要时使用后复权或不复权数据。

### _apply_board_params() 覆盖参数
**背景：** v35 策略的 init() 中自动调用 _apply_board_params()，将用户设置的类属性覆盖为板参数默认值，导致无论怎么调参数都无法产生交易。
**规则：** 使用 DragonFirstYin 时设置 _use_board_params = False 跳过覆盖。v36/v37 已从底层修复此问题。

### MACD/KDJ/Index 三过滤拦截率过高
**背景：** v35 同时开启 MACD+KDJ+板块指数三重过滤，创业板信号被过滤掉64%，导致大量本应捕捉到的龙首阴信号被拦截。
**规则：** 龙首阴策略是短线博弈策略，不宜叠加过多技术指标过滤。只需保留核心风控（非跌停、缩量、ATR合理、阴线深度可控）即可。

## 策略迭代记录

### v35 原始版
- 板参数覆盖问题导致无法运行
- 修复：新增 _use_board_params 开关
- 25只标的均收益：-0.15%

### v36 优化版（当前最优）
- 自适应涨停阈值（自动识别10%/20%涨跌幅）
- 简化过滤链（关闭MACD/KDJ/Index过滤）
- 移动止损（6%回撤/3倍ATR/12天时间止损）
- 25只标的均收益：+0.63%，正收益比60%
- 全量回测前100只信号数：76只（v35仅56只）
- 建议默认使用 v36

### v37 精选版
- 缩量确认+假阴线加分
- 自适应移动止损（ATR动态调整）
- 25只标的均收益：+0.33%，回撤控制更好
- 优化方向正确但参数偏保守，可继续调优
